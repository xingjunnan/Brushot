## 截图无法捕获 tooltip 的修复（CGEventTap 方案）

**根因**：macOS 的 tooltip/hover 弹窗在目标 App 收到修饰键（Cmd/Shift 等）事件时立即消除。SnapInk 的截图热键（如 Cmd+Shift+1）按下顺序：按 Cmd → App 收到事件消除 tooltip → Carbon 热键回调（AppKit 层）触发 → 已来不及。即使 Carbon 回调里同步 CGWindowListCreateImage 也截不到。

**方案**：新增 `TooltipPreCaptureEventTap`（main.swift），用 `CGEvent.tapCreate(tap: .cgSessionEventTap, ...)` 在事件派发给 App 之前拦截 `flagsChanged`：
- 修饰键上升沿（且与任一截图快捷键 modifiers 有交集）时同步 `PreCaptureStore.shared.capture()`，此时 tooltip 还在屏。
- 每次按键序列只截一次（`capturedThisHold` 标志，修饰键全松开时复位），避免后续修饰键按下覆盖含 tooltip 的帧。
- Carbon 回调改为 `if action == .capture && !TooltipPreCaptureEventTap.shared.isActive { capture() }`——EventTap 激活时不重复截（防覆盖），未激活时降级回原行为。

**权限**：CGEventTap 需要辅助功能（Accessibility）权限。新增 `requestAccessibilityPermission`：`AXIsProcessTrustedWithOptions` 弹系统对话框 + 轮询 60s。无权限时静默降级（截图可用，仅 tooltip 保不住）。

**健壮性**：tap 被系统禁用（tapDisabledByTimeout/UserInput）时回调里重新 enable；`applicationDidBecomeActive` 检测并重建 tap。

**坑**：
- Swift 6 严格并发下 `kAXTrustedCheckOptionPrompt`（C 全局变量）被判 non-Sendable 报错，改用字符串字面量 `"AXTrustedCheckOptionPrompt"`。
- CGEventTap 的 C API（`CGEventTapCreate/Enable/IsEnabled`）在 Swift 里被 obsoleted，须用 overlay `CGEvent.tapCreate/tapEnable/tapIsEnabled`。
- 首次把三个新方法错插到 `CaptureController`（因锚点 `requestScreenCapturePermission` 属于它），移到 `AppDelegate` 后才访问到 `tooltipEventTap`/`shortcuts`。

**验证**：`swift build --disable-sandbox` 通过（当前环境 sandbox-exec 被禁，需加 `--disable-sandbox`）；`swift test --disable-sandbox` 85 测试全过。

## "正在捕捉你的屏幕"横幅排查与修复

**现象**：macOS 14+ 菜单栏间歇性显示"SnapInk 正在捕捉你的屏幕"横幅，退出 App 后延迟消失。

**根因**：该横幅是系统针对 `SCStream`（ScreenCaptureKit 流式捕获）的指示。SnapInk 的普通区域截图在 `finishCapture` 中：预截图可用时走 `cropFromPreCaptured`（CGWindowListCreateImage，不触发横幅）；**预截图不可用时的 fallback 走 `makeScreenshot` → `ScreenRegionCapturer.capture()` → 启动一次性 SCStream → 横幅闪现**。预截图不可用 = EventTap 没截到 + Carbon 因 `isActive=true` 不兜底。

**修复**：把 `finishCapture` 的 fallback 改为优先 `preCaptureScreens()`（CG fallback）+ `cropFromPreCaptured`，仅当 CG 也失败才用 SCStream。这样单次截图不再触发横幅。同时在 EventTap/Carbon/fallback/makeScreenshot 四处加 NSLog 便于诊断 EventTap 工作状态。

**注意**：`beginAnnotationEditing`/`finishOCR` 的 fallback 仍用 makeScreenshot（SCStream），但因这些场景优先用预截图，触发概率低；长截图/GIF 本身需要 SCStream，横幅是预期的。

**二次修复（hasEntries 方案）**：上述 fallback 改 CG API 后普通截图仍触发横幅，根因是预截图一直空（EventTap 没截到 + Carbon 因 isActive=true 跳过）。改为：Carbon 回调不再看 isActive，而是看 `PreCaptureStore.hasEntries`——EventTap 截到就不覆盖（保 tooltip），没截到就 Carbon 兜底 capture（CG API）。这样预截图永远有，finishCapture 永远走预截图分支，不碰 SCStream。代价：EventTap 没截到时 tooltip 截不到（降级为无 tooltip），但横幅消除。

**日志诊断结果**：用户普通截图快捷键是 Option+Q（modifiers=2048=optionKey）。直接跑二进制抓 stderr：EventTap 安装成功（`tooltip-preserving event tap installed`），三次截图都触发 `eventtap precapture (mods=2048)`，**没有** `carbon fallback`/`finishCapture fallback`/`makeScreenshot` 日志——说明预截图成功、走 CG API、没碰 SCStream。之前看到的横幅是旧进程残留（装新 DMG 后没重启进程，旧进程被 kill 后系统延迟清除横幅指示器）。注意：NSLog 在此环境不进 unified logging（`log show`/`log stream` 抓不到），只能抓 stderr；`log --predicate` 在 zsh 报 "too many arguments"（引号被吃），用 grep 管道或 stderr 重定向替代。
