# Brushot 产品与技术决策

本文件记录已经确认的重要取舍。它不是不可变历史；用户明确改变方向时，应更新原条目或追加替代决策，并说明原因。

## DEC-001：保持原生菜单栏应用形态

- 状态：有效
- 结论：Brushot 继续作为 `LSUIElement` 原生 macOS 菜单栏应用，不增加常驻 Dock 主窗口。
- 原因：核心价值是快速唤起截图、录屏、标注和贴图，常驻主窗口会增加操作距离。
- 影响：设置、预览、OCR 和贴图库按需打开独立窗口。

## DEC-002：最低支持 macOS 13，并发布 Universal 2

- 状态：有效
- 结论：最低系统版本保持 macOS 13，同时构建 arm64 与 x86_64。
- 原因：兼顾 ScreenCaptureKit 能力与仍在使用的 Intel Mac。
- 影响：macOS 14/15 新 API 必须使用可用性判断，并为 macOS 13 保留兼容路径。

## DEC-003：录屏入口只保留区域、窗口和全屏

- 日期：2026-08-21
- 状态：有效
- 结论：移除“应用录屏”，保留“区域录屏”“窗口录屏”“全屏录屏”。
- 原因：大多数应用只有一个主要可见窗口，应用录屏与窗口录屏体验高度重合，额外入口增加理解和维护成本。
- 影响：不得恢复应用级多窗口捕获目标和交互，除非用户明确重新评估该需求。

## DEC-004：窗口录屏只捕获单个窗口

- 日期：2026-08-21
- 状态：有效
- 结论：用户悬停并单击哪一个窗口，就只捕获该窗口，不自动加入同一应用的其他窗口。
- 原因：行为明确、可预测，并与区域录屏和全屏录屏形成清晰边界。
- 影响：应用后续出现的新窗口或弹窗不会自动加入当前窗口录屏。鼠标悬停识别到窗口时就立即在窗口中央显示所属应用图标、真实应用名和实际像素尺寸，单击只负责锁定目标；窗口标题不作为应用名展示。

## DEC-005：窗口外透明区域使用黑色

- 日期：2026-08-21
- 状态：有效
- 结论：窗口录屏合成中，没有窗口像素覆盖的区域使用纯黑背景，不使用 ScreenCaptureKit 的白色不透明底色。
- 原因：大面积白色会刺眼，也容易被误解为录制错误；黑色更符合视频播放器和深色界面习惯。
- 影响：窗口录屏配置必须持有黑色 `CGColor` 的有效生命周期，且不能用会强制白底的配置覆盖它。

## DEC-006：实时标注进入成片，控制 UI 不进入

- 日期：2026-08-20
- 状态：有效
- 结论：矩形、箭头、画笔等实时标注需要烧入视频和 GIF；倒计时、边框、控制栏和其他 Brushot 窗口必须排除。
- 原因：标注是内容，控制 UI 只是操作工具。
- 影响：修改 ScreenCaptureKit 过滤器或覆盖窗口时，必须真实录制并抽帧验证两类窗口的包含与排除关系。

## DEC-007：保持稳定 Bundle ID、安装路径和签名身份

- 状态：有效
- 结论：Bundle ID 固定为 `com.brushot.app`，本地验证使用 `/Applications/Brushot.app`，构建优先复用已安装应用的有效签名身份。
- 原因：macOS TCC 权限与应用身份、签名和路径密切相关，随意变化会导致权限重复申请或失效。
- 影响：不使用临时 CLI 产物判断权限问题；修改签名或沙盒能力前必须说明影响。

## DEC-008：OCR 读取原始冻结画面

- 状态：有效
- 结论：OCR 始终读取进入标注前的冻结原图，不读取标注和水印后的扁平化结果。
- 原因：箭头、文字、马赛克和水印会污染识别结果。
- 影响：标注编辑器和长截图预览调用 OCR 时必须保留原始图像来源。

## DEC-009：视频录制默认使用 1080p / 30 帧/秒

- 日期：2026-08-21
- 状态：有效
- 结论：视频录制提供原始、4K、1080p、720p 与 15、30、60 帧/秒，默认 1080p / 30 帧/秒；确认栏分别标注“分辨率”和“帧率”，选择会被记住，GIF 继续使用独立的自动优化策略。
- 原因：1080p / 30 帧/秒在文字清晰度、流畅度、长时间录制稳定性和文件大小之间更均衡，同时保留高质量与低负载选项。
- 影响：分辨率按目标边界等比缩小，不裁剪、不添加黑边、不放大小画面；原始或 4K 搭配 60 帧/秒时显示高负载提示。

## DEC-010：摄像头画中画直接进入视频成片

- 日期：2026-08-22
- 状态：有效
- 结论：摄像头画中画只用于视频录制，作为可拖动、缩放、切换圆形 / 圆角矩形、小 / 中 / 大和左右翻转的实时覆盖窗口直接进入视频像素；GIF 暂不支持摄像头，也不引入录后图层编辑或项目文件。
- 原因：实时预览与成片一致，操作链路短，符合 Brushot 当前轻量录屏定位，同时避免引入完整视频编辑工程的复杂度。
- 影响：每次新录制的摄像头默认关闭；左右翻转首次使用默认开启，此后与设备、位置、尺寸和形状一样记住上一次选择。录制确认页把详细选项收进「画中画设置」，提供四角快捷定位与靠边吸附；首次权限请求完成前不得开始录制。录制中可临时开关摄像头并实时修改同一组设置。摄像头断开、占用或启动失败时只关闭画中画并持续显示异常状态，屏幕录制继续。录制控制栏、边框和倒计时仍不得进入成片。

## DEC-011：在系统磁盘压力前主动保护录屏

- 日期：2026-08-22
- 状态：有效
- 结论：磁盘可用空间低于 16 GB 时明确警告但允许用户继续，低于 12 GB 时禁止开始；录制中每 5 秒检查一次，低于 12 GB 时由 Brushot 正常收尾。录制确认栏不持续显示估算时长，仅在达到磁盘警告或阻止阈值时提示。
- 原因：真实日志确认本机约剩 10.4 GB 时，macOS 触发 `cacheDeleteUrgencyHigh`，`replayd` 随即调用 `stopAllStreamsWithError` 强制结束 ScreenCaptureKit 屏幕、系统音频和麦克风流；原 1 GB 门槛无法在系统介入前保护录制。
- 影响：在安全底线之上保留短时录制自由，接近系统压力范围时明确告知风险；低于安全底线则阻止或提前结束。系统仍意外停止时继续保留已有有效内容。

## DEC-012：区域录屏使用屏幕像素精确控制选区

- 日期：2026-08-22
- 状态：有效
- 结论：仅区域录屏在确认栏提供「选区 宽 × 高」入口，弹出面板内包含精确宽高、自由 / 16:9 / 4:3 / 1:1 / 9:16、比例锁定与上次区域；移除独立悬浮尺寸栏和手动保存区域。宽高按当前显示器实际像素展示和输入。全屏与窗口录屏不显示该入口，目标区域不可改成普通区域。
- 原因：精确尺寸与常用内容比例是 Screen Studio、Omi 和 Capso 等录屏产品的常见录前能力，可减少反复拖动和后期裁剪；同时必须避免把“屏幕选区大小”与“视频输出分辨率”混为一谈。
- 影响：Retina 屏幕上输入像素尺寸时需要按 backing scale 换算到逻辑坐标；恢复区域采用相对显示器的归一化坐标，以适应不同显示器尺寸。弹出面板避免遮挡录制格式、质量、音频和画中画选项。输出分辨率仍由原始 / 4K / 1080p / 720p 设置独立决定。
